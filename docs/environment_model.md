# 天候・クッション値・含水率の係数学習

## 運用原則

天候、馬場状態、クッション値、芝・ダート含水率は、予測から切り離された参考情報ではない。
JRAから取得可能な値、測定時刻、区分、注記、測定履歴、原文の来歴をすべて保存し、
当日の予測成果物と振り返り学習の双方へ渡す。

ただし「反映する」とは未検証の係数を作ることではない。観測値は常に予測入力として記録し、
勝率を動かす `environment_score` は時系列の検証・テストを通過して明示的に昇格したモデルだけが生成する。
昇格前は厳密に0とし、`NO_PROMOTED_ENVIRONMENT_MODEL` を保存する。これにより、データを捨てず、
かつ振り返り前の思いつきの補正を本番馬券へ混ぜない。

本番の勝率式は次とする。環境係数はMonte Carlo後のbaseline勝率へ、学習時と同じ形で適用する。

```text
p_base = current structural/pace Monte Carlo probability
p_final(i) = softmax(log(p_base(i)) + environment_score(i))
```

`environment_score` はレース共通値の単純加点ではなく、馬別特徴量との交互作用のlogit補正である。

## 勝率の式

既存モデルの勝率を `p0(i)` とし、候補モデルは次で定義する。

```text
score(i) = log(p0(i)) + Σ[h,e] β[h,e] × (horse[i,h] - mean_race(horse[h])) × env[e] / scale_train[h,e]
p(i) = exp(score(i)) / Σ[k] exp(score(k))
```

`horse` は先行度、末脚、走破速度、馬場適合度。すべて対象レースより前の過去走から作る。

`env` は雨・曇り・雪の指標、クッション値、ゴール前含水率、4コーナー含水率、馬場状態。
数値変数は固定の単位変換を行い、学習データだけから決めた尺度で標準化する。
候補にはクッション値・両含水率の二次項も用意し、線形式と二次式を比較する。

天候やクッション値は同じレースの全馬で共通のため、単純な加点ではSoftmaxから消える。
各馬の特徴との交互作用にすることで、相対的な勝率に影響する。
環境変数が学習期間内で一定なら、その効果は識別できないので対応する係数をゼロに固定する。

## 学習・採否

- レース単位の条件付き対数損失とL2正則化で係数を推定する。同着の単勝ラベルにも対応する。
- 日付単位で古い順に約60%・20%・20%へ分割する。同じ日の別レースを分割境界にまたがせない。
- 学習期間だけで係数と標準化尺度を推定し、検証期間だけで式と正則化係数を選ぶ。
- テスト期間は候補を選んだ後で評価する。テスト成績を見て式を再調整しない。
- 本番用の固定評価データ・評価スクリプト・既存の分割は変更しない。新しい時系列実験は別ファイルへ出す。
- 回収率は、別実験として事前に固定した「各レースの勝率1位を100円単勝」の成績を記録する。
  本番の全券種ポートフォリオ回収率とは区別する。
- 学習100・検証20・テスト20レースを運用上の最低件数とする。この件数自体が精度を保証するものではない。
  雨・クッション値・両含水率・馬場状態の変動も必要。
- 検証・テストの対数損失改善、テストBrierスコア非悪化、両期間の単勝ポリシー回収率非悪化を確認する。
  合格しても本番モデルのファイルは自動上書きしない。

### 単一日の事後再構成から行う研究fit

既に結果を確認した日の研究fitは、`experiment_kind=posthoc_exploratory_training_only`
の別実験として記録する。訓練日は単一の日付に固定し、検証日・test日は空、
`labels_previously_inspected=true`、`preregistered_before_label_inspection=false`、
`production_eligible=false` を保存する。既存の10月24日訓練・10月25日検証の実験は
変更せず、この別実験の成績を既存実験の独立検証やtestとして使用しない。

この接続は市場列を生成も参照もしない厳格な芝向け基本形を使用し、監査用途を
`environment_structural_research` と明示する。この用途だけは今回の人気・オッズの
欠損を補完候補に数えず、同じ列の値が特徴量へ混入した場合は停止する。
過去オッズを含む履歴の必須観測、全36レースの原典照合、全PASSレース集合と各レースの
全馬・必要履歴、未承認補完禁止のゲートは維持する。非対応条件や不合格レースは理由を
保存し、欠損馬だけを除外して通過させない。

候補は従来の研究用二段階Softmaxと固定の線形モデル・ridge=100で計算し、訓練内指標
としてのみ報告する。学習日・環境測定日・発走日時・候補の訓練最終日を同じ固定日へ
束縛する。単一日のfitは条件の多様性や将来日の精度を証明せず、上記の最低件数・
時系列検証・test・本番昇格条件を満たしたことにはならない。

### 移管データセットの研究トラック取り込み（準備段階証拠の採用）

2026-11-08、ユーザーは移管データセット（`research/datasets/jra-20260502-20260927`、
全1,464レース）について、準備段階の証拠を研究トラックの取り込み根拠として認める
判断をした（task-management Issue #39、コメント 6722973492）。

経緯：公開アーカイブは原典本文を含まない設計（`source_document_bodies_included=false`）
のため、中核監査のハッシュ拘束再解析（VERIFIED_REPARSE）はアーカイブ単体では
実施できず、厳格ゲートは全候補がUNVERIFIEDに留まる。この判断により、次の
準備段階証拠が再解析の代替として、研究トラックに限り認められる。

- 対象レースの `audit_preparation` 記録がPASSであること
- 原典インデックスに対するSHA来歴チェーンが未結線0件で全件結線すること
- データセット検証（manifest・SHA-256・件数の照合と `verify_dataset.py`）がPASSであること

代替が認められるのは再解析の部分だけであり、次は従来どおり全て必須とする：
必須欠損なし、未承認補完なし、履歴件数の完全性、取得ギャップなし、構造契約
エラーなし、結果リークなし、環境ゲートPASS。判定は
`scripts/audit_dataset_strict_gate.py` の合成層 `evaluate_research_admission`
が行い、厳格ゲート（`gate` / `model_ready`）自体の意味は変えない。

記録の正直さ：

- 取り込み記録は `evidence_basis='preparation_stage'` を明示し、検証状態は
  アーカイブ単体の値（UNVERIFIED）のまま保持する。VERIFIED_REPARSEへの
  読み替えは行わない。
- 取り込まれたレースは `posthoc_exploratory_training_only`、
  `production_eligible=false` のままで、本番昇格の最低件数（学習100・検証20・
  テスト20）には算入しない。

この判断で変わらないもの（非対象）：

- `purpose='prediction'` の監査・ゲートの挙動、本番昇格条件、Stage 0の
  発走前収集の要件。
- 芝向け基本形の契約範囲。ダート候補は本判断の対象外であり、取り込みには
  ダート基本形の拡張が別途必要である。

初回適用は2026-11-08の実行（`report/research/dataset_20260502_20260927_training_20261108T145738Z/audit/`）
で、芝218レースを取り込み、研究プールは芝236レースとなった。ダート80候補は
馬場契約により未取り込みのままである。（この状態は2026-11-09のダート基本形
拡張で更新された。次節参照。）

### ダート基本形の拡張（2026-11-09）

2026-11-09、ユーザーの指示（「ダートも学習用に使おうよ」）により、構造研究の
契約にダート基本形を追加した（正は `structural_features.py` の
`SURFACE_BASE_FORMS`、方針は [条件別モデル方針](condition_models.md) の
「馬場種別基本形」節）。これにより、前節で対象外だったダート候補も、同じ
準備段階証拠の経路で研究トラックへ取り込めるようになった。

ダートの環境契約:

- 必須はダート含水率（ゴール前と4コーナーの両方）で、当日・発走前の測定
  であることを要求する。含水率をダートの馬場状態の連続量として中心に置く。
- クッション値は芝コースの測定値であり、ダートでは `NOT_APPLICABLE`
  （必須とせず、流用もしない）。芝含水率もダート含水率へ流用しない。
- 芝の環境選択・ゲート結果は無変更である。障害は別カテゴリのままで対象外。

適用結果: 2026-11-09の実行（`report/research/dataset_20260502_20260927_training_20261108T154310Z/audit/`）
でダート80レース（学習47・検証13・テスト20）を取り込み、研究プールは
芝236・ダート80となった。最大のダートセルは新潟1800mと札幌1700mの各10レース。
取り込みのラベル（`evidence_basis='preparation_stage'`、
`posthoc_exploratory_training_only`、`production_eligible=false`）は芝と同一。

この拡張で変わらないもの:

- 本番昇格の要件と本番経路。Stage 0の発走前収集（ダート含水率の発走前
  キャプチャを含む本番スキーマ）が本番の唯一の経路であり、このアーカイブは
  事後再構成の研究専用であることに変わりはない。
- 環境係数のfit接続（単一日の事後再構成fit）は芝向けのままである。ダートの
  環境係数学習は、含水率を中心変数として今後別途検証する。

## 実行

```bash
.venv/bin/python scripts/train_environment_model.py
```

入力は `data/evaluation/fixed_race_last5.csv`、`fixed_result_labels.csv` と、
`data/environment/official_measurements.json`。公式測定値は競馬場と測定日で厳密に結合し、
別日の値で補完しない。天候未取得、ダートに芝クッション値を流用するケース、測定値未取得は除外し理由を出す。
出走前の天候公表時刻の厳密な監査は、データ拡張時の追加課題として記録する。

出力先は `report/environment_model/`。学習データ、候補係数、分割、全試行の検証成績、
入力ファイルSHA256、除外理由、採否を保存する。

2026-10-18の初回実行では、結果付き固定データ8レースから芝6レースを使用できた。
学習3レースの天候はすべて曇りで雨の効果を識別できず、件数も不足している。
試験係数は `candidate_not_promoted` として保存し、本番勝率や正式買い目へ採用しない。

## 今後の自動収集と学習の蓄積

通常の `scripts/run_pipeline.py` は `DataCollectorAgent` から、直前予測は
`LiveSnapshotCollector` から環境データを毎回取得する。
JRA出馬表の天候・馬場状態も更新し、古い出馬表キャッシュの天候を最新観測として使わない。
クッション値と芝・ダートのゴール前／4コーナー含水率を公式のデータファイルから取得する。
取得には既存のHTTPリトライを使用する。

取得した値、測定時刻、取得時刻、公式URL、原文HTML名とSHA256、欠損・取得失敗理由は
`report/environment_observations/<race_id>/` に時点ごとに保存する。
当日分の未公表、前日分しかない、発走後の取得、発走時刻未設定などの場合は
`eligible_for_learning=false` とし、正式な環境係数の学習材料にしない。
キャッシュだけの再処理では元の観測時刻を保持し、取得時刻を新しく付け直さない。
直前処理では追加の取得時間も締切管理に含める。

学習に使える観測が取れた時点で、その時点の過去走入力も `cases/` へ保存する。
後からレース別の最新成果物が上書きされても、発走前に記録した学習材料は保持する。
観測値と天候予測値を区別し、予測値を過去の実測値として学習させない。

結果の登録は既存コマンドを使用する。

```bash
.venv/bin/python scripts/append_result_labels.py --review-json report/<race_review>.json
```

このコマンドは結果の登録後、`scripts/update_environment_learning.py` の処理を呼ぶ。
保存済みの発走前データと結果ラベルを結合し、データが増えれば係数を再推定する。
ラベル未登録のレースは学習に含めず、観測不足のレースは理由を保留一覧へ記録する。
同じラベル・同じ観測を繰り返し処理してもデータ件数を水増ししない。
同じ競馬場・同じ日の同一測定値は共有でき、値が矛盾する場合は処理を停止する。

```bash
.venv/bin/python scripts/update_environment_learning.py
```

で手動再集計もできる。結果と候補係数は
`data/learning/environment/<dataset_sha256>/<model_code_sha256>/` に保存し、最新の学習状況は
`report/environment_model/learning_status.json` へ出力する。
元の固定評価ファイルは上書きしない。採用条件を満たすまでは本番係数を変更しない。

## 発走時の環境と展開の統合

学習が成立した後は、天候予報から作る環境シナリオごとに、その環境変数で勝率を計算する。
馬場・クッション値・含水率の予測値は観測値と別フィールドで保存する。
現在の `analysis/environment_scenarios.py` は係数学習前の感度分析用であり、
この学習済みモデルと混同しない。

ハイ・ミドル・スローごとの連系確率を計算し、
`P(ticket) = Σ[environment,pace] P(environment,pace) × P(ticket | environment,pace)`
で統合する。平均単勝確率だけから三連複確率を作る近似と区別し、
モデルの妥当性が確認できるまでは「回収率の最適化に成功した」と評価しない。

## 本番昇格

学習レポートが `ELIGIBLE_FOR_REVIEW` の場合だけ、レビュー後に次を明示実行する。

```bash
.venv/bin/python scripts/promote_environment_model.py \
  --training-report data/learning/environment/<dataset>/<code>/training_report.json \
  --approve
```

昇格成果物は `data/models/environment_model.json` に保存される。通常分析と直前分析は同じ成果物を読み、
モデルID・モデルSHA256・観測SHA256・適用可否・未適用理由をstage JSONへ保存する。
別日値、発走後値、予測値を観測値として補完することは禁止する。
