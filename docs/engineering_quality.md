# AI開発の品質原則

## 中心原則

> 守れるルールは、プロンプトではなくコードで強制する。

AIへの指示は確率的であり、見落とし、解釈違い、過剰対応が起こり得る。同じ入力に同じ判定を返せるルールは、AIや人間の注意力に依存させず、Linter・型・テスト・静的解析・CIへ移す。

レビューで繰り返し指摘するルールは、レビュー項目として残さない。機械判定できるものは品質ゲートへ移し、違反したコードがPRに到達しない仕組みにする。AIと人間のレビューは、要件、設計、影響範囲など判断が必要な領域に集中させる。

## ルールの配置先

| ルールの性質 | 実装先 |
| --- | --- |
| 構文、命名、記述方法、禁止API | Linter |
| import方向、レイヤー依存 | 静的なアーキテクチャ検査 |
| 型の整合性 | 型システム |
| 入出力、境界値、期待動作 | 自動テスト |
| ビルド、カバレッジ、品質基準 | CI |
| セキュリティの既知パターン | 静的解析、依存関係検査 |
| 要件の抜け漏れ、意味的な影響範囲 | AIと人間 |
| 設計の妥当性、例外、トレードオフ | 人間（AIは判断材料を提示） |

判断の入口は「Yes／Noで機械的に判定できるか」とする。判定できる場合は、レビュー手順への追記より先にコード化を検討する。

## このリポジトリの品質ゲート

`scripts/check_quality.sh` をローカル、pre-commit、CIの共通入口とする。現在は次を強制する。

- RuffによるPythonの未定義名、未使用importなどの静的検査
- `src/agents` の役割間import禁止、およびagentからorchestratorへの逆依存禁止
- 学習・戦略コードへの結果情報混入を検出するfeature leakage検査

全テストとカバレッジは `scripts/preflight.sh` で実行し、pre-pushとCIで強制する。ローカルhookは `scripts/install_git_hooks.sh` で導入する。

```bash
scripts/check_quality.sh  # 高速な決定論的チェック
scripts/preflight.sh      # 品質チェック + 全テスト + カバレッジ
```

既存コードへ新しい検査を導入するときは、既存違反を放置したまま無効化しない。既存違反を修正して一度に有効化するか、対象範囲を明示した段階導入にし、拡張条件を記録する。Ruffは現在、既存コードが満たすcorrectnessルールから開始している。

## 運用フロー

1. 開発ルールと理由をこの文書または対象領域の設計文書に記録する。
2. Yes／Noで判定できる部分を抽出し、最も適切な強制手段へ実装する。
3. 検査自体の正常系と違反系をテストする。
4. `scripts/check_quality.sh` または `scripts/preflight.sh` に統合し、ローカルとCIで同じコマンドを使う。
5. AIエージェントはPR作成前にゲートを実行し、自身の変更による違反を修正する。
6. PRでは自動化できない要件、設計、影響範囲、エッジケースをレビューする。
7. 同じ指摘が繰り返されたら、Linterルール候補としてIssue化または本文書の候補欄へ追加する。

## レビューの役割分担

自動化は、コーディング規約、命名、ディレクトリ構造、import制約、既知のエラー処理やログ規約、テストの定型を担当する。

AIレビューは、要件との不一致、不自然な実装方針、複数ファイルにまたがる影響、エッジケースを探す。自動ゲートの結果を言い換えてレビューコメントを増やさない。

人間は、ビジネス要件、優先順位、設計上のトレードオフ、例外を認めるか、将来の保守性を判断する。

## 例外とルール追加

機械ルールの例外は、行単位の無言な無効化を原則禁止する。例外が必要なら、理由、適用範囲、見直し条件をコードコメントまたは設計文書に残す。広い除外設定より、最小範囲の抑制を選ぶ。

新しいルールは次を満たしてから必須化する。

- 違反メッセージから修正箇所と理由を特定できる
- 正常なコードを過剰に拒否しない
- 違反を再現するテストがある
- ローカルとCIで同じ結果になる
- 自動修正が安全なら、その実行方法が明記されている

## 自動化候補

レビューで反復した指摘をここへ追加し、十分に機械判定できるものから品質ゲートへ移す。

- 型検査の対象範囲を、境界モジュールから段階的に広げる
- ログ出力と例外処理のプロジェクト規約を定義して静的検査する
- Ruffの規則をimport順、命名、複雑度へ段階的に広げる
- 依存関係と既知脆弱性の検査をCIへ追加する
