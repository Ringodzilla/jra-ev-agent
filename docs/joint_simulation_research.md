# 走力・環境・価格を接続する研究用モンテカルロ

今回追加したのは計算部と観測抽出であり、全データを学習した本番予測モデルではない。公開予測CLIの基本形・係数・購入条件は変更していない。

## 役割別の接続

- data_collectorは、馬体重・増減、公開時刻または公開観測区間、同じ馬の単勝時系列、クッション値・芝/ダート含水率・測定時刻、全過去走の事実を収集する。過去走の `weight` は斤量であり、馬体重へ流用しない。
- analyzerは、履歴と当日条件の交互作用から構造勝率・環境効果の研究drawを作る。市場担当の価格反応モデルは、体重発表前後の観測から学習し、発表済み情報を含む現在価格へ同じ反応を二重適用しない。増量や減量の効果の符号・大きさは固定しない。公開前の予測では体重自体の不確実性も学習データから扱う。
- simulatorは、同じ試行・同じ全馬集合の構造確率、環境logit、価格反応を対にしたdrawを復元抽出する。`analysis/joint_monte_carlo.py` の `simulate_joint_trials` はseed付き乱数を実際に使い、馬単位で依存関係を壊して組み替えない。
- 構造確率へは市場価格を混ぜない。各試行で `p_final=softmax(log(p_base)+environment_logits)`、`odds_trial=current_odds*exp(market_log_odds_response)` とし、EVは対応した試行の積の平均を使う。`E[p×odds]` と `E[p]×E[odds]` を区別する。
- 出力は試行、馬別の勝率・価格・EVの平均と5/50/95%分位、勝率順位・EV順位。分位は与えた研究drawの分布であり、校正済み信頼区間や人間を上回る性能の証明ではない。

研究drawは必須で、欠けた効果を0や任意ノイズで埋めない。ライブラリはcallerのlineageを保存するが、それ自体を監査合格や昇格の認定にしない。実レースの新規研究計算は既存の収集・欠損/補完承認・研究工程を通し、未検証の効果を本番へ投入しない。市場反応と走力の相関も、単純な独立仮定ではなく供給するjoint drawに根拠を持たせる必要がある。

## 馬体重とオッズの観測

`analysis/body_weight_market.py` の `observe_body_weight_market` は明示的な公開時刻の前後を照合し、実測のlogオッズ変化と増減比を返す。未来・発走後・他馬・別レースの価格を除外し、未測定はnullと理由を返す。取得時刻を公開時刻には変換しない。この観測も他の市場情報を含むため、体重の因果効果そのものではない。

`scripts/build_body_weight_panel.py` は未公表snapshotと公表済みsnapshotを照合する。菊花賞では18頭の14:21→14:51価格変化を確認できたが、公開上限の観測は14:52頃で、後側の価格も公開後と証明できない。従ってこれは時点間変化のパネルであり、公開前後反応の学習例18件と数えない。`later_quote_confirmed_after_publication` を残し、公開時刻を創作しない。

## 残る実データ作業

現行の過去paceと体重はモデルへ未接続。v4の保存原典では過去馬体重が構造化されていない。これらを回収して検証可能な学習データへ変換し、条件別・時系列分離で研究drawを生成・比較する必要がある。現時点で有効性が検証された全特徴量のjoint drawは存在せず、実レースの全データ反映勝率や推奨馬はこの実装からまだ発行していない。

## 展開を固定して候補を絞る

`analysis/pace_conditioning.py` の `simulate_pace_conditioned` は、各source drawに明示された `pace=high|mid|slow` を引き継ぎ、MC試行の頻度から展開分布を出す。これは供給元の予測drawに基づく分布であり、未学習の任意ラベルを付けただけで実レースの展開を予測できるものではない。現在のfront densityから作る既存のheuristic重みと、学習した展開モデルは別に表示する。

最多ペースや手動指定は仮説として比較できるが、統計確認前には本線を確定しない。同率最多も未確定として残し、EVが高い展開や結果を見て都合よく選び直さない。条件付き勝率 `P(馬の勝利|展開)` と全体勝率 `Σ P(展開)P(馬の勝利|展開)` を別保存し、両者の整合を検算する。試行0件の展開は不可能や勝率0とはせず未評価にする。

`analysis/pace_candidates.py` は各試行の条件付き勝率から既存canonical順位モデルで8券種の的中確率を計算し、同じ展開内で平均する。馬連等について「平均勝率から計算した確率」を「試行ごとに計算して平均した確率」の代わりにしない。繰り返し出現する同じsource drawは1回だけ計算して頻度で加重する。この候補評価では同一snapshotの公式組番オッズを固定して使い、連系の価格変動を予測済みとは扱わない。

`strategy/pace_selection.py` の `select_pace_candidates` は指定展開の的中確率・EVだけに明示された閾値を適用する。券種別に既存設定の閾値を渡し、単勝勝率を連系的中率として流用しない。他展開の感度と全体確率を参照として残す。金額配分・正式GO・自動購入はこの研究APIの出力ではない。

確定本線の接続順序は `simulate_until_pace_advantage` → `build_pace_candidates` → 券種ごとの `select_confirmed_pace_candidates`。単なる条件比較には `simulate_pace_conditioned` と `select_pace_candidates` を使えるが、統計確認済みの本線とは扱わない。本番切替は未実施で、全特徴量から予測drawを供給する実データ経路と時系列検証が引き続き必要である。元のスコアが平坦な問題を、展開の固定だけで解決済みとは扱わない。


## 優位差の確認と追加試行

`analysis/adaptive_pace.py` は初回試行数、追加バッチ数、最大試行数、有意水準alpha、確認したい最小確率差min_gapを事前に明示して実行する。確認する累積試行数はその設定だけで決まり、途中の成績によってバッチ幅やseedを変更しない。同じ固定draw集合から同じ乱数系列を継続し、優位差を確認するか、上限に達するまで追加する。

`analysis/pace_advantage.py` は各ペアの差を `Y=I(pace_a)-I(pace_b)` とし、範囲[-1,1]に対する片側Hoeffding限界を用いる。k回目の確認で6組の順序付きペアそれぞれへ `delta=alpha/[6k(k+1)]` を配分する。差の下限は `観測差−sqrt(2 log(1/delta)/n)`。全競合への下限がmin_gapを厳密に超えたときだけ確定する。全kで配分和がalphaとなるため、事前固定した累積試行数での繰り返し確認と、多重比較を考慮できる。固定nの通常の95%区間を何度も見て、都合よく止める方法ではない。

全lookの回数・累積counts・上下限・差・alpha配分・追加試行数・停止理由を保存する。上限で未確認なら本線を固定せず、条件別・全体の評価を保持する。手動指定と統計的な最多ペースが異なる場合も、手動仮説を統計確認済みとしない。確定本線用の候補選定入口は検査履歴を再検算し、文字列のペース指定や真偽値だけでは統計確認済みにしない。

この保証は、固定したiid bootstrap母集団に対するMC標本誤差に限る。元のdraw集合の学習量、モデルの誤り、実レースの展開精度、馬の勝率の校正は改善したと宣言しない。同じデータからの追加試行を独立した実レース検証件数に数えない。人工データの動作例ではalpha=.05、min_gap=.03としたが、本番用の設定を採用したものではない。

参考：Hoeffding (1963), [Probability Inequalities for Sums of Bounded Random Variables](https://doi.org/10.1080/01621459.1963.10500830)。逐次確認と停止時点を考慮する必要性は Howard et al. (2021), [Time-uniform, nonparametric, nonasymptotic confidence sequences](https://arxiv.org/abs/1810.08240)。本実装は後者の特定の境界を実装したものではなく、上記のHoeffdingと事前固定lookへのalpha配分による検査である。
