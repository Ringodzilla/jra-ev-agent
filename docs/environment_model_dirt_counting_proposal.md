# ダート観測の数え方（定義案）と下流監査の記録

状態: **未承認の案**。本書は `docs/environment_model.md` の現行定義を一切変更しない。
数え方の定義が承認されるまで、Stage 0 のダート観測は「蓄積中・未カウント」として扱う
（`scripts/capture_stage0_day.py --status` の `dirt_counting` に理由つきで表示される）。
関連: task-management Issue #39（Stage 0 = ワークストリーム B）。

## 1. 現行定義との関係（2026-11-12 確認）

- `docs/environment_model.md` の「学習・採否」は、運用上の最低件数を
  学習100・検証20・テスト20レースと定めるが、**馬場別の数え方は定義していない**。
  この最低件数は現行の学習経路（芝のみが学習対象。次節参照）に紐づくものであり、
  ダート観測をそこへ算入する根拠は現行 docs のどこにもない。
- 同 docs の「ダート基本形の拡張（2026-11-09）」は研究トラックの取り込み契約であり、
  「本番昇格の要件と本番経路は変わらない」と明記する。Stage 0（発走前収集）における
  ダートの昇格カウントは未定義のままである。
- したがって本タスクでは数え方を新設しない。ダート観測は保存・集計され、
  学習ステータス上は未カウントであることが理由とともに分かる形にした。

## 2. 定義案（承認された場合に environment_model.md へ追記する文面の案）

> ### Stage 0 におけるダート観測の数え方（案）
>
> - Stage 0 のダート観測は、芝の最低件数（学習100・検証20・テスト20）とは
>   **別枠**で数える。芝とダートを合算して最低件数を満たしたとはみなさない。
> - ダート側の最低件数は、ダートの環境係数学習（ダート含水率を中心変数とする学習経路）が
>   別途検証され接続されるまでは設定しない。それまではダート観測は蓄積のみとし、
>   昇格判定の対象にしない。
> - 分割（学習・検証・テスト）は芝と同一の時系列原則（日付単位・古い順）でダート単独に
>   適用する案とするが、件数の確定は学習経路の接続時に行う。

この案は提案であり、承認なしに昇格条件・`MINIMUM_RACES`・分割へ組み込まない。

## 3. 下流の芝前提の切り分け（2026-11-12 監査記録。挙動変更はしていない）

対象は Stage 0 の fold-in 経路（`scripts/update_environment_learning.py` →
`scripts/train_environment_model.py: build_training_races` →
`analysis/environment_model.py`）。

| 箇所 | 芝前提 | ダート観測が混ざった場合の挙動 |
| --- | --- | --- |
| `build_training_races` の理由判定 | 対象レースの `target_surface != '芝'` を最初に判定 | **理由つきで除外される**（`turf_cushion_not_applicable_to_dirt`）。黙って無視されず、誤って学習されることもない。学習レポートの `excluded_races` に残る |
| `build_training_races` の計測マージ | 計測は `(競馬場, 日付)` 単位で共有され、馬場別ではない。照合キーには `cushion`・`cushion_measured_at` を含む | 同日・同場で「クッション値を持つ計測」と「クッション欠落が正当なダート計測」が衝突すると `ValueError: Conflicting measurement` で**停止する**（fail-closed。値の矛盾で止めるのは docs の既存方針どおり）。黙って混ざることはない |
| `build_training_races` の計測時刻検証 | 学習対象レースについて `cushion_measured_at` の存在と午前中であることを必須とする | 芝レースの計測としてクッション欠落のダートスナップショットだけが残る状況では `KeyError` で**停止する**。これも fail-closed であり、誤学習にはならない |
| `analysis/environment_model.py: environment_vector` | `cushion` と `turf_moisture_goal/corner4` を必須とする設計（芝の環境ベクトル） | ダート環境 dict が渡れば例外で落ちる。ただし現行経路では `build_training_races` がダートを先に除外するため**到達不能**。ダートの環境係数学習は含水率中心の別経路が未接続であり、本前提はその接続時に扱う |
| `analysis/environment_model.py: train_and_compare` | 最低件数・分割は馬場非依存の実装 | 現行は芝レースだけが入力されるため実質芝の判定。ダートが入力される経路は存在しない |

結論: 現行の下流は、ダート観測を「理由つきで除外する」か「矛盾時に停止する」かの
いずれかで処理し、**黙って無視する箇所も、誤って学習する箇所もない**。
この監査に基づく学習挙動の変更は行っていない。計測マージの (競馬場, 日付) 共有は、
将来ダート学習経路を接続する際に馬場別の保持を検討すべき論点として記録する。
