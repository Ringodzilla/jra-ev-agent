# 買い目構築

共通契約と実行順は [工程仕様](../../docs/skill_workflow.md) を読む。担当役割は `bet_builder`。他工程の値を黙って修正しない。

- 前提・入力JSON: 08 PASS、ユーザー予算、券種方針。
- 出力artifact JSONの必須内容: `core, partner, long, bet_types_considered, candidate_counts, tickets`
- 合格条件: 8券種横断候補と除外理由、点数・総額・実オッズ・ポートフォリオ評価を保存。予算内。
- 停止条件: 確率やオッズを改変しない。欠損券種を無断で推定しない。出力は候補で正式推奨にしない。

入力・出力のパス、SHA256、取得/評価時刻、コード検査の実結果を共通 envelope に残す。検査未実行を PASS としない。

## 根拠のある高EV候補を残す

- 高オッズ、低人気、過去着順のばらつき、履歴件数だけを理由とした追加の強制除外をしない。単勝30倍超×安定性0.30等の撤去済みルールを復活させない。データ欠損・補完承認の監査は前工程で扱う。
- 実装済みの確率・EV・予算・点数・オッズ変動・選定条件を用い、候補集合から選ぶ。除外は適用した設定値・実測値・理由を示し、独自の「安全性」条件を足さない。
- 候補、条件通過、最終選定を区別する。買い目0件の場合も、最も有望な候補と何の条件で不成立だったかを具体的に示す。必ず買うための条件緩和もしない。

- 展開固定の研究候補は、本線の条件付き的中確率とEVで絞る。他展開の感度・全体評価も保存し、条件付き勝率を無条件の的中保証と扱わない。研究APIの候補を正式GOとして出さず、本番への切替は既存の検証・判断を通す。

- 本線の展開固定には統計的優位差を確認する。初回・追加・上限の試行数と有意水準・最小差を事前固定し、同一乱数系列で試行を追加する。繰り返し確認と複数ペース比較を考慮し、上限でも未確認なら本線を固定しない。MC誤差の減少と実レースでの精度・学習データ量を混同しない。手動指定は仮説比較として残し、未確認の最多ペースを確定済みとして渡さない。
