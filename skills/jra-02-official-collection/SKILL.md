# 公式データ収集

共通契約と実行順は [工程仕様](../../docs/skill_workflow.md) を読む。担当役割は `data_collector`。他工程の値を黙って修正しない。

- 前提・入力JSON: 01 の PASS。公式出馬表・全履歴・環境・8券種オッズ。
- 出力artifact JSONの必須内容: `race_info, horses, raw_artifacts, history_counts, environment, odds`
- 合格条件: 取得元URL・取得時刻・原文SHA256を保存し、取得不能項目を明示。取得成功と完全性を分ける。
- 停止条件: 別日値・別馬値・推定値で埋めない。結果データを発走前入力へ混ぜない。

## 欠損回収と取得不能の判定

- GETの失敗、パラメータエラー013、parserの空欄だけでは「公式に情報がない」と判定しない。原文に値がないのか、取得方法・解析が対応していないのかを分ける。
- 過去走の上がり・通過順・天候・単勝オッズが欠ける場合は、公式の競走馬成績から該当する過去結果へ進む。オッズは結果ページ内の実在する `doAction('/JRADB/accessO.html', '...')` を辿る。GETで失敗したら、フォームに従いPOSTで `cname` を送信する。既存 `JRAScraper.fetch_post` を利用できる。キーの大文字小文字も原典に合わせ、CNAMEやチェックサムを創作しない。
- HTTP 200だけで成功とせず、正常な単勝表と対象の日付・競馬場・レース・馬番・馬名を照合する。別レースや今回のオッズ、払戻からの逆算値で代用しない。対象レース自身の発走後データは取得・入力しない。
- 同一過去レースのHTMLは再利用する。GETで保存したエラーページをPOST成功のキャッシュとして再利用せず、method・URL・送信パラメータ・取得時刻・原文SHA256・馬別対応を保存する。
- 原典回収後は新しい収集artifactを保存し、回収前の補完指摘を履歴として保持して現状の集計を更新する。監査へ渡して入力SHA256と欠損・補完を再検証し、回収済み項目への補完承認は求めない。
- 公式の通常経路と上記POST経路でも回収できなければ、試した経路と応答を残して停止理由を報告する。同じ失敗を無期限に繰り返さない。取得方法の失敗を理由に、先に手入力や補完承認を依頼しない。

入力・出力のパス、SHA256、取得/評価時刻、コード検査の実結果を共通 envelope に残す。検査未実行を PASS としない。

## 分析に渡せる事実を集める

- 過去走ペース・通過順と当日環境は、現行モデルで未使用でも取得可能な原典を回収する。「未使用」を「不要」や「取得不能」に置き換えない。
- 同一原典のキャッシュを共有し、正常応答からの解析失敗と原典欠落を分ける。解消可能な不足は収集担当で解決し、同じ依頼や監査を繰り返すだけで締切を消費しない。

## 馬IDによる過去出走履歴の回収と実出走数の確認

- 出馬表の履歴が5走未満、履歴行の必須項目に空欄、または原典と件数が不一致なら、data_collectorは対象馬の公式競走馬成績を確認する。出馬表内の実在リンクから公式馬ID・URLを特定し、同一馬と照合して履歴を再取得する。5行あるだけで項目欠損の回収を省略しない。
- `horse_id` が馬名正規化による代替IDなら公式IDとして使わない。リンクなし・ID不明では公式出馬表の再取得と実在リンクの確認を行い、未解決なら識別未確認とする。IDからJRAのCNAME・チェックサム・URLを創作しない。公式画面のリンク/フォームを辿る。
- 年齢だけで出走数を推定しない。対象レースより前の公式出走履歴・通算成績から、確認済み通算出走数とその対象範囲（中央・地方・海外）、履歴の全件表示/ページ送り、対象レース日時を確認する。現在の通算成績に対象レース以後の出走が含まれる場合は、その数を事前必要件数に流用しない。取消・除外等は出走と区別する。
- 必要件数は `min(5, 確認済みの対象レース前通算出走数)`。公式に2走だけと確認できた馬の2走取得は件数充足であり、残り3走を欠損・補完扱いにしない。0走確認も件数上は充足だが、特徴量算出可否や補完の承認は別途監査する。若齢や取得行数だけでは通算数確認済みにしない。
- 正常応答・解析成功だけで全履歴取得と断定しない。ページ欠落、解析失敗、地方/海外走の未収録、通算数不明は `UNVERIFIED`、確認済み必要件数より少ない場合は `MISSING` とし、原典上の短いキャリアと区別する。出走数充足でも時計・通過順等の項目欠損は別に回収・監査する。
- 収集JSONの `history_counts` に馬ID・ID種別・URL・対象時点・通算数（不明はnull）・通算数の原典/範囲・必要/取得/不足件数・件数判定を保存する。再取得のmethod・パラメータ・取得時刻・原文SHA256、ページ範囲、失敗理由も残す。取得した履歴は同一過去走を照合して重複排除し、対象レース以後の走を除外して直近5走を選ぶ。項目別来歴を保持して03へ渡す。
- 現行CLIは埋込履歴5走未満で `horse_url` を取得するが、5走の項目欠損では同分岐を通らない。短いキャリアの自動判定も `force_rebuild` 等の条件付きであり、上記確認の代替にはしない。必要な原典確認は収集担当が行い、スキル追記だけでCLIの全ケース自動回収が実装済みとは説明しない。
