# 公式データ収集

共通契約と実行順は [工程仕様](../../docs/skill_workflow.md) を読む。担当役割は `data_collector`。他工程の値を黙って修正しない。

- 前提・入力JSON: 01 の PASS。公式出馬表・全履歴・環境・8券種オッズ。
- 出力artifact JSONの必須内容: `race_info, horses, raw_artifacts, history_counts, environment, odds`
- 合格条件: 取得元URL・取得時刻・原文SHA256を保存し、取得不能項目を明示。取得成功と完全性を分ける。
- 停止条件: 別日値・別馬値・推定値で埋めない。結果データを発走前入力へ混ぜない。

## 欠損回収と取得不能の判定

- GETの失敗、パラメータエラー013、parserの空欄だけでは「公式に情報がない」と判定しない。原文に値がないのか、取得方法・解析が対応していないのかを分ける。
- 過去走の上がり・通過順・天候・単勝オッズが欠ける場合は、公式の競走馬成績から該当する過去結果へ進む。オッズは結果ページ内の実在する `doAction('/JRADB/accessO.html', '...')` を辿る。GETで失敗したら、フォームに従いPOSTで `cname` を送信する。既存 `JRAScraper.fetch_post` を利用できる。キーの大文字小文字も原典に合わせ、CNAMEやチェックサムを創作しない。
- HTTP 200だけで成功とせず、正常な単勝表と対象の日付・競馬場・レース・馬番・馬名を照合する。別レースや今回のオッズ、払戻からの逆算値で代用しない。対象レース自身の発走後データは取得・入力しない。
- 同一過去レースのHTMLは再利用する。GETで保存したエラーページをPOST成功のキャッシュとして再利用せず、method・URL・送信パラメータ・取得時刻・原文SHA256・馬別対応を保存する。
- 原典回収後は新しい収集artifactを保存し、回収前の補完指摘を履歴として保持して現状の集計を更新する。監査へ渡して入力SHA256と欠損・補完を再検証し、回収済み項目への補完承認は求めない。
- 公式の通常経路と上記POST経路でも回収できなければ、試した経路と応答を残して停止理由を報告する。同じ失敗を無期限に繰り返さない。取得方法の失敗を理由に、先に手入力や補完承認を依頼しない。

入力・出力のパス、SHA256、取得/評価時刻、コード検査の実結果を共通 envelope に残す。検査未実行を PASS としない。
