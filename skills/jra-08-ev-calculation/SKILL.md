# 確率・EV再計算

共通契約と実行順は [工程仕様](../../docs/skill_workflow.md) を読む。担当役割は `ev_calculator`。他工程の値を黙って修正しない。

- 前提・入力JSON: 07 PASS、オッズsnapshotと公式時刻。
- 出力artifact JSONの必須内容: `ev_table, probability_checks, odds_lineage, formula_version`
- 合格条件: 07の確率・来歴・検査結果を引き継ぎ、有限性と同一入力を照合してEV=p×oddsを再検算。単勝と連系の確率を区別。既存CLI内の機械検算と別の勝率推定を独自に追加しない。
- 停止条件: 古いオッズ、未確認確率、確率来歴不一致で停止。高EVを勝率の妥当性の証拠にしない。

入力・出力のパス、SHA256、取得/評価時刻、コード検査の実結果を共通 envelope に残す。検査未実行を PASS としない。

## 価格差を見える形にする

- 全候補について的中確率・現在オッズ・現在EVと、オッズ変動を考慮したEVを区別する。実装にない不確実性補正や保守係数を追加しない。
- 高EVが馬固有の評価から生じたのか、勝率の平坦さと高オッズの組合せなのかを説明する。算術一致と勝率モデルの識別力・校正を混同しない。
- 単勝の勝率と複勝・連系の的中確率を混ぜない。高い単勝EVだけから複勝や相手候補の購入を正当化しない。

- 同時点の価格と固定構造確率の差を、05・06の根拠と結び付けて説明する。「市場が見落としている」は検証仮説として示し、単なる高オッズや一律勝率と同じ候補集合を独自の発見と呼ばない。

- 展開固定の候補評価ではその展開の券種別的中確率を使い、現在の公式価格によるEVと価格シミュレーション込みのEVを区別する。連系確率は対応試行で計算して平均し、平均勝率からの代用と混同しない。
